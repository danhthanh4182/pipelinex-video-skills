# Build Code Explainers

1. Write a question, target audience, language, duration, and the one thing a viewer should understand. Break the answer into a hook, two to four explanatory chapters and one closing takeaway.
2. Build a storyboard with `start`, `duration`, `narration`, `visual`, `source` and what should be readable at the end of each beat. Link on-screen claims, numbers and quotations to approved sources. For a map, use approved geographic data and distinguish schematic routes from physical routes.
3. Build original diagrams and typography with the existing PipelineX Remotion components or another local composition chosen for the brief. Let the voice step establish duration, use word marks for captions, and derive chapter markers from scene starts. For Vietnamese, choose a voice and fonts that support diacritics and check proper names.
4. Preview the hook, the densest scene, each chapter boundary and the final hold. Check that a chart retains its units and scale, and that map movement leaves text and credits legible. Keep audio and timed captions with the timeline.
5. Treat [anything2explainer](https://github.com/Vincentwei1021/anything2explainer) as a workflow reference. Its toolkit is licensed under PolyForm Noncommercial. Confirm authorization before reusing that toolkit for commercial production. For a PipelineX job, prefer composing from the project's existing local components.
